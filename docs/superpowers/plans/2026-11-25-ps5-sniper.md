# Makler PS5 Sniper Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hourly cloud monitor of PS5 listings on makler.md with Telegram alerts and an iPhone widget.

**Architecture:** Python package `sniper/` run by a GitHub Actions cron; state in `data/state.json` committed back to the repo; Scriptable widget reads `data/widget.json` via raw.githubusercontent.

**Tech Stack:** Python 3.12, requests, beautifulsoup4, pytest; GitHub Actions; Telegram Bot API; Scriptable (JS).

**Spec:** `docs/superpowers/specs/2026-11-25-ps5-sniper-design.md`

## Global Constraints
- Never request `/an/search` (robots.txt). Only the category URL with the user's city filter.
- ≥2 s pause between page requests; max 25 pages; UA string identifies a browser.
- Secrets only from env: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. Never in files.
- Deal threshold `deal_usd = 650`; rates in `config.json`.
- State is written only after a successful crawl (≥1 page parsed with ≥1 listing).

## Review Focus
- Site returns Cloudflare challenge / 403 / empty page → no state change, failure counter +1, alert only after 3 consecutive failures, recovery message once.
- Telegram fails mid-run → listing not marked `notified`, retried next run (no loss, no dupes).
- Bumped old listing (same ID, new time) → no notification.
- Price in "договорная"/missing → included, usd=None, never treated as a deal or drop.
- Photo send fails (bad URL) → fallback to text message.
